# 사용자 흐름과 화면 설계

대상 사용자와 완료할 핵심 행동에서 시작한다. 기존 UI와 디자인 규칙을 먼저 확인하고 서비스 맥락에 맞는 화면을 설계한다.

## 진행

- 진입부터 완료까지 핵심 흐름을 정리하고 각 화면이 담당하는 사용자 목표를 적는다.
- 화면마다 정상 상태와 필요한 로딩·빈 결과·실패·권한 없음·완료 상태를 정한다.
- 폼은 필수 입력, 검증 시점, 오류 위치, 중복 제출 방지, 성공 후 이동을 구체화한다.
- 주요 행동의 우선순위, 키보드 접근, 포커스 이동, 라벨과 오류 안내, 작은 화면의 동선을 확인한다.
- 내용과 위계를 먼저 정하고 색상·타이포그래피·간격을 일관되게 정한다. 서비스와 무관한 장식이 핵심 행동을 가리지 않게 한다.

## 구현으로 전달

화면 전체 조합은 `screen/`, 기능을 가진 조각은 `component/`, 도메인 지식이 없는 시각 요소는 `ui/`로 분리한다. 라우트 파일은 화면 연결과 라우트 경계 처리를 맡긴다.

필요하면 `docs/ux.md`에 화면별 목적, 진입·완료 경로, 상태, 주요 행동, 연관 요구사항 ID를 남긴다. 작은 변경은 해당 티켓에 기록해도 된다.

인증·권한, 데이터 노출, 필수 사용자 흐름을 바꾸는 선택은 사용자 결정 항목으로 표시한다. 시각적 세부 사항은 합의된 방향 안에서 진행한다. 프로토타입이 실제 저장·통신을 하지 않으면 그 상태를 명확히 한다.

## 검토

사용자가 다음 행동과 처리 결과를 알아볼 수 있는지 시나리오를 따라 확인한다. 정적 시안만으로 실제 접근성이나 동작이 검증됐다고 표현하지 않는다.

## 실행 비용

확정된 화면의 상태 목록과 안내 문구 초안은 경량 역할에 맞는다. 핵심 흐름과 정보 구조 변경, 상충하는 사용자 요구는 일반 또는 심층 역할로 판단한다.
