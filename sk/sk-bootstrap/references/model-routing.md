# 모델과 effort 선택

이 문서는 스킬 수행 비용을 조절하는 정책이다. 제품 자체에서 AI API를 호출하는 설계는 별도 요구와 결정으로 다룬다.

## 작업별 선택

| 역할 | 작업 | 예시 설정 |
|---|---|---|
| 도구 | 파일·스키마·종료 코드·포맷·타입 등 결정적 검사 | 모델 호출 없이 스크립트·검사 도구 사용 |
| sk-fast | 좁은 범위 탐색, 확인된 사실 추출·분류, 반복 문서 정리 | gpt-6-luna / low |
| sk-worker | 명확한 인수 조건과 계약이 있는 일반 구현 | gpt-6.1-sol / medium |
| sk-deep | 요구 충돌, 주요 설계 비교, 복잡한 오류·권한·정합성·성능 원인 | gpt-6.1-sol / high |

모델명은 교체 가능한 예시다. 설정 시 사용 가능한 모델과 지원 effort를 확인한다. Astra는 사용하지 않는다. 경량 모델이 낮은 effort에서 해당 작업을 안정적으로 수행하는지도 실제 결과로 판단한다. 검증하지 않은 모델이나 비용을 보장하지 않는다.

스킬에 고정된 모델을 붙이지 않는다. 코드 리뷰의 파일 수집은 fast, 결함 판단은 worker 또는 deep처럼 같은 스킬 안에서도 작업 성격에 맞춘다. 최종 판단이 단순한지, 실패의 영향과 확인 가능성이 어떤지를 함께 본다.

## 실제 실행

- SKILL.md의 텍스트나 `agents/openai.yaml`의 UI 메타데이터는 모델 전환 설정이 아니다.
- Codex에서 지원하면 `.codex/agents/*.toml`의 `model`, `model_reasoning_effort` 또는 위임 도구의 명시적 모델·effort 인수를 사용한다. 실제 적용 여부는 런타임이 제공하는 실행 정보로 확인한다.
- 현재 주 에이전트가 스킬을 읽는 것만으로 자신의 모델·effort를 실행 중 바꿀 수 있다고 가정하지 않는다.
- 특정 역할·모델 지정 기능이 없으면 현 모델로 처리하고 비용 절약이 구현됐다고 주장하지 않는다. 다른 서비스 API 호출로 조용히 대체하지 않는다.
- 현재 모델이 Astra이면 그 모델로 계속 작업하지 않고 다른 모델 선택이 필요함을 알린다. 모델 상향과 위임에서도 Astra를 선택하지 않는다.

## 위임 비용

짧은 작업은 현재 에이전트에서 끝낸다. 같은 종류의 독립적인 단순 작업은 묶어 한 역할에 맡긴다. 모든 티켓에 세 역할을 순차 호출하지 않는다. 필요한 파일·요구사항·완료 조건·예산만 전달하고 근거가 있는 짧은 결과를 받는다.

역할은 다시 다른 역할을 생성하지 않는다. 주 에이전트가 범위와 예산을 관리한다. 전체 대화·저장소·원시 로그를 매번 전달하지 않는다. 이미 확보한 조사·검증 결과는 코드와 환경이 같고 현재 판단에 유효하면 재사용한다.

## 상향과 중단

요구 충돌, 원인 불명 실패, 재현 결과와 가설의 불일치, 권한·데이터 정합성 문제는 상향 검토 후보다. 도구 부재·자격증명 부재·외부 서비스 장애는 높은 effort로 해결된다고 가정하지 않는다.

프로젝트에서 허용한 모델·effort·예산 안에서 상향한다. 사용자에게 주요 제품·기술 결정을 대신하지 않는다. 동일 실패가 연속 2회이고 새 근거가 없으면 현재 방법을 멈추고 원인 가설·도구·역할을 변경한다. 변경한 역할도 같은 티켓 예산을 이어받는다.

기본 반복 한도는 티켓당 수정 사이클 3회, 경과 15분 중 먼저 도달하는 조건이다. 전체 작업의 시간·사용량 한도가 있으면 함께 적용한다. 실제 토큰 수를 얻을 수 있을 때만 토큰 기준을 사용한다. 재시도·위임을 포함한 총사용량으로 효과를 판단하며 절약 수치를 만들어내지 않는다.
