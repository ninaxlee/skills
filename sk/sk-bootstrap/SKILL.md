# 서비스 개발 환경 초기화

현재 저장소와 지침을 읽고 새 프로젝트인지 기존 앱의 보완인지 구분한다. 서비스 범위와 사용자가 확정한 기술 선택을 따른다.

Astra는 사용하지 않는다. 검색 도구를 통한 웹 검색·문서 조회는 허용한다. 브라우저 화면 조작·Computer Use·브라우저 자동화 E2E는 사용하지 않는다. 화면 확인은 사용자에게 절차를 안내하고 터미널·API 검사와 구분한다.

## 초기 판단

- 런타임·패키지 관리자·잠금 파일·기존 실행 명령·현재 프레임워크 버전을 확인한다. 설치나 생성 명령은 해당 도구의 현재 공식 문서를 확인한다.
- React 또는 Next.js와 NestJS를 기본 후보로 삼는다. 사용자 선택이 없고 서비스 요구가 선택을 좌우하면 대안·비용·권고안을 제시하고 선택을 기다린다.
- DB·ORM·인증·배포 제공자·모노레포 도구를 기본으로 끼워 넣지 않는다. 실제로 필요한 의존성과 운영 요소만 준비한다.
- 기존 파일을 덮어쓰기 전에 내용을 비교해 보완한다. 구현과 무관한 폴더 이동이나 사용자 전역 설정 변경을 하지 않는다.

## 초기화

1. 선택된 도구로 앱과 서버의 최소 실행 골격을 만든다. 새 버전·보안 상태·호환성은 실제 설치 시 확인한다. 불필요한 예제 기능은 초기 범위에 포함하지 않는다.
2. 웹은 `src/ui`, `src/component`, `src/screen`을 분리한다. 라우트는 화면 연결과 프레임워크 경계, screen은 화면 조합, component는 기능 조각, ui는 도메인 없는 시각 요소를 맡는다. 의존 방향은 `route → screen → component → ui`이며 상위에서 ui를 직접 참조할 수 있다.
3. React 라우터 또는 Next.js의 예약 라우트 파일은 screen을 연결하도록 둔다. NestJS는 기능 단위 모듈과 명확한 HTTP·유스케이스 경계를 만든다.
4. 필요한 실행·타입·린트·빌드 명령과 테스트 도구를 준비한다. 처음부터 모든 종류의 테스트 인프라를 추가하지 않는다.
5. 개발 포트, 프런트 API 주소, 필요한 CORS·프록시, 환경변수 예시를 정리한다. 실제 비밀을 생성 문서나 예시에 넣지 않는다.
6. 최소 API 요청과 앱·서버 빌드를 확인하고 화면 연결은 사용자 확인 절차를 안내한다. 실패하면 원인을 구분하고 프로젝트 반복 예산 안에서 수정한다.

## AI 작업 환경

[모델 선택 정책](references/model-routing.md)을 읽고 실제 런타임이 지원하는 모델·effort·역할 설정을 확인한다. 설치된 스킬 이름이 모델 전환을 보장한다고 설명하지 않는다.

- [AGENTS.md 템플릿](assets/AGENTS.md.template)을 현재 프로젝트의 경로·실행 명령·문서 위치로 채운다. 기존 AGENTS.md가 있으면 관련 내용만 합친다. 미설정 토큰을 남기지 않는다.
- 역할 설정이 지원되면 [경량](assets/codex/agents/sk-fast.toml), [구현](assets/codex/agents/sk-worker.toml), [심층 검토](assets/codex/agents/sk-deep.toml) 예시를 바탕으로 `.codex/agents/`에 필요한 역할을 만든다. 예시 모델의 계정 접근 가능성과 effort 지원을 확인하고 맞게 바꾼다.
- 예시의 정책은 이번 프로젝트에서 사용하는 모델·역할과 일치시킨다. 실제 위임이 불가능하면 현재 모델에서 범위를 줄여 처리하고 그 한계를 알린다.
- 에이전트 파일로 실제 읽기 전용 권한이나 별도 sandbox가 생긴다고 보장하지 않는다. 검토 역할의 수정 금지는 행동 지침이다.

## 완료 보고

실제 생성·보완한 구조, 실행 명령, 모델 역할과 지원 여부, 실행 확인 결과, 남은 사용자 결정과 미검증 항목을 보고한다. 템플릿을 복사한 것만으로 환경 구성이 끝났다고 하지 않는다.
