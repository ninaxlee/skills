# 근거 있는 구현 설명과 질의응답

실제 요구사항, 코드, 결정 기록과 검증 결과를 읽고 설명을 만든다. 설명 대상과 시간이 주어졌으면 맞춘다.

## 질문 만들기

다음 가운데 서비스에 실질적인 질문을 고른다.

- 어떤 사용자 문제를 해결하며 이 흐름을 우선한 이유는 무엇인가?
- React 또는 Next.js와 NestJS의 책임을 어떻게 나눴는가?
- ui/component/screen 분리가 변경과 재사용에 어떤 영향을 주는가?
- 다른 저장·인증·구현 방식과 비교해 무엇을 선택했고 비용은 무엇인가?
- 중복 요청, 권한 위반, 동시 수정, 부분 실패가 나면 어떻게 되는가?
- 쿼리·요청·렌더링 낭비를 어떻게 확인했고 어떤 근거로 개선했는가?
- 무엇을 실제로 검증했으며 현재 한계와 다음 우선순위는 무엇인가?
- AI의 제안 중 무엇을 채택·수정·기각했고 판단과 검증은 어떻게 했는가?

## 답변 형식

각 질문에 짧은 답변, 코드·결정·검증 근거, 트레이드오프, 예상 꼬리 질문을 붙인다. 중요한 질문은 반례와 대안을 들어 답변의 약한 부분을 확인한다.

선택 당시 기록이 없으면 “현재 코드를 기준으로 분석하면”이라고 구분한다. 구현되지 않은 확장과 검증하지 않은 성능을 현재 성과처럼 설명하지 않는다. 근거가 없으면 답변을 꾸미지 말고 확인할 위치·실험을 제시한다.

문서가 필요하면 `docs/explanation.md` 등에 핵심 데이터 흐름, 주요 선택과 한계, 우선순위 높은 질문을 남긴다. 이미 있는 결정·구조 문서를 긴 문장으로 반복하지 않는다.

연습을 요청하면 질문을 하나씩 제시하고 사용자 답변 뒤에 정확성·근거·명료성 피드백과 다음 질문을 제공한다. 사용자가 충분하다고 하면 종료한다.

## 실행 비용

확정 사실의 요약과 질문 초안은 경량 역할, 반례 분석과 답변의 타당성 검토는 일반 또는 심층 역할로 처리한다. 질문 수를 늘리는 것보다 중요한 선택의 근거를 확인한다.
