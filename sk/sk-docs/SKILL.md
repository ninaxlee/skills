# 코드와 일치하는 문서

기존 문서와 코드·실행 설정을 먼저 확인한다. 대화에서 제안한 내용을 구현 완료 사실과 구분한다.

## 문서 선택

- README: 서비스 설명, 필요한 실행 환경, 설치·실행·검증 명령, 환경변수 이름과 설정 방법.
- 요구사항: 요구 ID, 범위, 인수 조건과 현재 상태.
- 구조·API: 실제 폴더별 책임, 프런트·서버 경계, 요청·응답·오류와 데이터 흐름.
- 결정 기록: 비교한 대안, 사용자 선택, 근거와 재검토 조건.
- 작업·검증: 티켓 상태, 요구사항 연결, 관찰한 결과와 미검증 항목.

작은 프로젝트는 문서를 합친다. 같은 내용을 여러 파일에 복제하지 않고 원본으로 연결한다. 전체 문서 묶음을 매번 생성하지 않는다.

## 사실성

- 실행 명령은 실제 scripts와 도구 설정을 확인한다. 실행하지 않았으면 미실행임을 알린다.
- 환경변수는 이름·용도·필수 여부·예시만 적고 실제 비밀 값을 복사하지 않는다.
- 화면·API·저장이 mock이면 명시한다. 구현 예정 기능과 실제 동작을 섞지 않는다.
- 설명과 코드가 다르면 실제 동작과 확정 요구의 차이를 먼저 표시한다. 문서만 바꿔 미충족 요구를 감추지 않는다.
- `ui`, `component`, `screen` 책임과 실제 경로를 설명한다. 없는 폴더를 있는 것처럼 쓰지 않는다.

## 활용 기록

의미 있는 경우에만 AI 제안, 사용자 판단, 기각·수정 이유, 검증 결과를 관련 티켓·결정에 짧게 남긴다. 프롬프트 전문을 의무적으로 기록하지 않는다. 당시 기록이 없으면 사후 분석임을 구분하고 사용량·시간·생산성 수치를 만들지 않는다.

## 실행 비용

확인된 사실을 양식에 정리하는 작업은 경량 역할로 묶는다. 코드와 기록의 불일치를 해석하거나 새로운 설계 근거를 만드는 작업은 일반 역할로 검토한다. 새로운 결정이 필요한 내용은 문서 작성 중 임의 확정하지 않는다.
